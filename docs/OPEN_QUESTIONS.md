## 2. Требуют решения человека (P1)

| № | Вопрос | Контекст | Как закрыть |
|---|---|---|---|
| Q-05 | Как менять «основной референс» после `approved`? | После approve основной референс закреплён навсегда; для смены нужна колонка `primary` на уровне владельца или ослабление S15-триггера (`ROADMAP_MARY_STUDIO.md`, WP-04A «Открыто») | Решение о схеме БД + миграции (только по разрешению) |
| Q-06 | Нужны ли DELETE/архивация для локаций и предметов? | В библиотеке (`app/api/library.py`) нет удаления; `ReferenceAsset`/сущности остаются навсегда | Решение: soft-delete (статус/флаг) без миграции или архивация с миграцией |
| Q-07 | Список финальных попыток для клипа: ручной approve или явный список? | Экспорт принимает явный список клипов (`clips` в `POST /api/projects/{id}/exports`), но не решает, какая попытка шота «финальная» | Решение: использовать `shots.approved_attempt_id` (уже есть) или вести отдельный список |
| Q-08 | Монтаж: достаточно склейки + музыки или нужны переходы/титры? | `app/assembly.py` делает trim → scale/pad → concat (`DECISIONS.md` §4.8) | Решение о следующем объёме экспорта |
| Q-09 | Где хранить аудио песни и нужны ли стемы? | Сейчас трек — `artifacts` проекта (`projects.audio_artifact_id`, §4.10); стемы не поддерживаются | Решение: один трек достаточно или нужен набор стемов/несколько дорожек |
| Q-10 | Принимаем ли качество речи в LTX-аудиодорожке? | У NLB-31 второй поток `aac` 48 kHz stereo, `volumedetect` mean −21.7 dB; внятность речи и совпадение артикуляции не проверялись (`ROADMAP_MARY_STUDIO.md`, NLB-31) | Прослушать ролики и зафиксировать вывод; при «нет» — TTS/lip sync выходит в приоритет |
| Q-11 | Planner: оставить `gemma3:4b` советующим или менять модель? | Vision-модель не распознаёт alias персонажей (`ROADMAP_MARY_STUDIO.md`, WP-05A «Открыто») | Принять текущее поведение (fallback + `needs_review`) или выбрать другую локальную модель |
| Q-12 | Нужен ли широкий референс сцены для NLB-31? | Танцевальный шот читается только в верхней части корпуса — нет approved wide-кадра (`ROADMAP_MARY_STUDIO.md`) | Решение о досъёмке/внешней подготовке кадра и его утверждении |
| Q-13 | Показывать ли рекомендованный пресет рендера в UI? | `GET /api/presets` есть, UI-индикатора нет (WP-M7) | Решение: панель на `#/shots` или оставить только CLI/API |
| Q-14 | `--preset <name>` при недоступном API: тихий fallback или ошибка? | Сейчас воркер печатает warning и берёт встроенные умолчания (WP-M7) | Решение: оставить fallback ради устойчивости или падать с ошибкой ради явности |
| Q-15 | Нужен ли `GET /api/lipsync/engines` (список и статус движков)? | Сейчас есть только `POST /api/shots/{id}/lipsync` с 409 (WP-M8) | Решить при выборе движка (Q-01), до реализации UI-формы |
| Q-16 | Нужна ли E2E-автоматизация загрузки файлов через браузерный диалог? | Загрузка проверена на уровне API и backend-тестов, UI-диалог не автоматизирован (`ROADMAP_MARY_STUDIO.md`, WP-04A «Открыто») | Решение: оставить ручную проверку или добавить браузерный тест |
| Q-17 | Нужен ли живой прогресс (SSE) вместо polling? | `JobProgress` опрашивает детали job каждые 3 с; SSE не реализован (`ROADMAP_MARY_STUDIO.md`, WP-06 «Открыто») | Решение о приоритете; сейчас polling устраивает |

| Q-39 | Доступность и разрешённость `powermetrics` для измерения энергии | Энергия «Дж/ролик» честно измеряется только с root (`RENDER_ENERGY_BENCHMARK.md` §7) | `sudo powermetrics --samplers cpu_power,gpu_power -i 1000 -n 5` и решение человека о разрешении |
| Q-40 | Тестовый шот и seed для бенчмарка, а также допустимость 3 preview-прогонов в варианте D | Без фиксации шота/seed сравнение несостоятельно; вариант D отклоняется от «один шот» (`RENDER_ENERGY_BENCHMARK.md` §3–§4) | Утвердить шот (предложение NLB-24) и seed; разрешить/запретить preview-серию для D |
