## 1. Цель и рамки

Мини-серия из пяти последовательных роликов (≈8 с каждый) с одним персонажем —
соболиным бурманским котом Guinness — в одной ночной квартире. Формат 9:16,
кинематографичный фотореализм, единая палитра и камера.

Цель — **максимальное качество в пределах измеренного бюджета памяти**, а не
максимальные значения настроек. Измерения 2026-11-04 (NLB-25, Eco):

| Метрика | Значение | Источник |
|---|---|---|
| Разрешение / кадры / fps | 576×1024 / 193 / 24 | `render_attempts.parameters` |
| Длительность | 8,042 с | `ffprobe` артефакта `af057b6c…` |
| `peak_mem_mb` | 16295 (из 18432 МБ) | `render_attempts.parameters` |
| `min_available_mb` | 2137 | там же |
| `max_pressure_level` | 4 (critical) | там же |
| `low_ram` | false | `workflow_snapshot` |
| Профиль | `eco`, питание `ac` | там же |

Вывод: даже базовый профиль доходит до critical по memory pressure. Поэтому
**одновременное** увеличение разрешения, числа кадров, steps и числа моделей
запрещено, а следующий GPU job после `critical` блокируется (см. ACCEPTANCE §4).

Вне рамок: изменение кода backend/worker/UI, миграции, новые зависимости и модели,
перегенерация NLB, монтаж с титрами и переходами, lip sync.

## 3. Проект

Название: `Guinness: Night Shift` · Русское: `Гиннесс: Ночная смена`.

Штатного `POST /api/projects` нет. Единственный существующий путь создания проекта —
`python -m app.import_series --create-project` по JSON-манифесту (WP-N1), он же
создаёт сцену, пять шотов, motion-ревизии и связи с референсами. Альтернатива
(создание только проекта) потребовала бы нового скрипта — это отдельное разрешение.

Схема: один проект → одна сцена «Ночная смена» → пять шотов `GNS-01…GNS-05`
(`sequence_no` 1…5). Каждый шот получает собственный стартовый кадр.

Запись персонажа (`characters`) в новом проекте штатным API не создаётся: таблица
заполняется только legacy-импортом. Поэтому работаем на **project-level**
референсах (`reference_assets.project_id`, `role='guinness_identity'` и
`role='gns_XX_start'`), как это уже сделано для NLB-21…27. Внешность держится
стартовым кадром, а не карточкой персонажа.

### 4.1 Расхождения «стартовый кадр → действие»

Это риск качества, а не ошибка данных. Для каждого случая подготовлен
альтернативный промпт-вариант; заменять дословный текст задания можно только с
разрешения человека.

| ID | Наблюдение | Вариант (на утверждение) |
|---|---|---|
| GNS-01 | Кот уже смотрит вверх, в окно; поворот к камере читается хорошо | без изменений |
| GNS-02 | Лапа уже **касается** фантика — «tap once» может не прочитаться | «lifts its paw slightly and taps the wrapper once …» |
| GNS-03 | Кадр — шаг/бег навстречу камере; промпт требует именно бег | «trots quickly forward, then slows and stops …» |
| GNS-04 | Лапа уже лежит на чашке | «rests its paw against the cup and pushes it a short distance …» |
| GNS-05 | Кот уже лежит с поднятой головой; «reclines» — статичная фаза | «settles deeper into the sofa, then lifts its head …» |

## 5. Continuity-контракт

1. **Внешность.** Соболиный бурманский кот: шоколадная маска, тёмные уши и хвост,
   тёплый коричневый корпус, жёлто-зелёные глаза. Один и тот же кот во всех пяти
   сценах; ни один шот не вводит второго кота.
2. **Палитра.** Тёплый янтарный интерьер (лампа, дерево) + холодный лунный синий из
   окон. Без насыщенных красных/зелёных акцентов, кроме фантика в GNS-02.
3. **Свет.** Ночь; единственные источники — луна/город за окном и тёплая лампа.
   Направление ключевого света согласовано: слева-сзади окно, справа тёплый прибок.
4. **Камера.** Фиксированная, «низкая» точка на уровне кота, одна непрерывная
   склейка на сцену; без зумирования, панорам и смены ракурса внутри шота.
5. **Анатомия.** Четыре лапы, естественная походка, без лишних конечностей и
   «морфинга» морды; уши и вибриссы двигаются правдоподобно.
6. **Квартира.** Одна и та же квартира: окно с балконной шторой, деревянный пол,
   длинный коридор, кухонный стол, диван.
7. **Стартовые кадры.** У каждой сцены — свой кадр; коллаж из пяти сцен как единый
   вход I2V запрещён. Identity-портрет не используется как интерьерный стартовый кадр.
8. **Провенанс.** У каждой попытки сохраняются `parameters` (размер, кадры, cfg,
   seed, preset, thermal, `workflow_snapshot`), артефакты неизменяемы.

## 6. Производственные этапы

| Этап | Что делается | Артефакт / проверка | Разрешение |
|---|---|---|---|
| P0 | Preflight (этот пакет) | пять документов, БД только read-only | — |
| P1 | Создание проекта и структуры | `import_series --dry-run` → отчёт, затем `--apply` | нужно |
| P2 | Загрузка identity и пяти стартовых кадров | 6 `reference_assets` со статусом `draft` | нужно |
| P3 | Approve референсов (человек) | статус `approved`, S15 далее запрещает правки | человек |
| P4 | `keyframe` из референса + `promote-keyframe` | `shots.start_keyframe_artifact_id` заполнен у 5 шотов | нужно |
| P5 | Preflight серии | `POST /api/projects/{id}/series/preflight`: `start_frames` 5/5 | — |
| P6 | По одному production-рендеру | 5 прогонов по 1 шоту, ревью после каждого | по одному |
| P7 | Ревью и approve попыток | `approved_attempt_id` выставляет только человек | человек |
| P8 | Финальная сборка ≈40 с | `POST /api/projects/{id}/exports` + `audio_artifact_id` | нужно |

Порядок P6 жёсткий: ни один следующий рендер не ставится в очередь до отчёта по
предыдущему (память, thermal, журнал, качество).
