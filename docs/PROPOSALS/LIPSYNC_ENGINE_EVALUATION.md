## 3. Ключевое ограничение: коты ≠ человеческие лица

Все известные нейросетевые lip-sync движки построены вокруг **детекции и разметки
человеческого лица**:

- Wav2Lip: 96×96 кроп рта, детектор лиц S3FD;
- MuseTalk: DWPose (позы/лицо) + face-parsing;
- LatentSync, SadTalker: 3DMM/face landmark и face restoration.

На морде кота эти детекторы либо не срабатывают, либо дают нестабильные точки. Значит,
для них нужен либо отдельный датасет котов и fine-tune, либо ручная маска лица на каждый
кадр — это выходит за границы текущих WP и требует GPU-обучения.

> **[ПРОВЕРИТЬ]** гипотезу «детекторы не находят лицо кота» одним прогоном выбранного
> детектора на approved-кадре GNS-05 (команда — в §8, шаг 0). До проверки это оценка
> по документации моделей, а не измерение.

Следствие: «настоящий lip sync» для Мэри Студии должен быть либо **2D-виземами**
(аудио → фонемы → формы рта, без распознавания лица), либо нейросетевой re-synthesis
морды, который сейчас нереализуем в ограничениях R2–R5.

## 4. Кандидаты

### 4.1. Wav2Lip

- Тип: нейросетевой pixel-level, 96×96 область рта, human-face.
- Лицензия: README прямо ограничивает использование **personal/research/non-commercial**;
  коммерческие запросы — через Sync Labs. Ограничение README распространяется и на
  веса детектора лиц, входящие в репозиторий.
- Железо: PyTorch, рассчитан на CUDA; CPU возможен, но медленно.
- Вердикт: **отклонён** по R3 (лицензия не подходит, Q-04 открыт) и R4.

### 4.2. MuseTalk (TME Lyra)

- Тип: latent inpainting области рта, real-time на NVIDIA V100 (30 fps+).
- Лицензия: **MIT** (LICENSE, Tencent Music, 2024); зависимости: sd-vae (MIT), whisper
  (MIT), face-parsing (MIT), DWPose (Apache-2.0) — по тексту LICENSE.
- Железо: официальная установка — Python 3.10 + CUDA 11.7; сторонние гайды называют
  ~8 ГБ VRAM. Поддержка macOS/MPS официально не заявлена.
- Вход: видео с лицом (или изображение), human face detection/parsing.
- Вердикт: **отклонён сейчас** по R2 (CUDA-центричный стек) и R4 (человеческое лицо);
  лучший кандидат на будущее, если появится NVIDIA-машина и датасет котов.

### 4.3. LatentSync (ByteDance)

- Тип: diffusion lip sync, 512×512 (v1.6).
- Железо: минимум **8 ГБ VRAM (v1.5)** и **18 ГБ VRAM (v1.6)**; CUDA.
- Лицензия кода/весов в этом WP не проверялась, поскольку кандидат отсечён по железу.
- Вердикт: **отклонён** по R2/R5 (18 ГиБ VRAM при 18 ГиБ общей памяти Apple Silicon
  и уже работающем LTX-воркере).

### 4.4. SadTalker

- Тип: talking head из одного портрета, 3DMM + face renderer.
- Лицензия: код Apache-2.0; но собранные веса опираются на исследовательские модели
  (BFM/GFPGAN и face reconstruction) с ограничениями — статус весов **[ПРОВЕРИТЬ]**.
- Железо: есть инструкции для macOS Apple Silicon; CPU-режим медленный, тяжёлый стек.
- Вердикт: **отклонён** по R3 (неясные веса) и R4; как и MuseTalk, требует лица человека.

### 4.5. Rhubarb Lip Sync

- Тип: **2D lip sync по фонемам**, без распознавания лица. Аудио → 6 базовых форм
  (Ⓐ–Ⓕ) + 3 расширенных (Ⓖ, Ⓗ, Ⓧ) с таймингами; форматы TSV/XML/JSON/DAT.
- Лицензия: **MIT**, включая третьи зависимости; результат работы принадлежит
  пользователю (`LICENSE.md`).
- Платформы: Windows, macOS, Linux; последний релиз **1.14.0 (2025-04-03)**,
  macOS-архив **82,8 МиБ**.
- Вход: WAV или OGG. Распознаватели: `pocketSphinx` (английский, по умолчанию) и
  `phonetic` (для не-английских записей); `--dialogFile` с текстом реплики заметно
  повышает точность.
- Железо: CPU, без GPU; отдельный процесс CLI.
- Применимость к котам: **вид не важен** — анализируется только звук; формы рта рисуются
  нашей существующей маской/калибровкой.
- Ограничение: это не фотореалистичный рот, а смена 2D-форм; зубы/язык не появляются.
- Вердикт: **рекомендован** как первый шаг (R1–R8 выполняются).

### 4.6. Allosaurus (запасной)

- Тип: универсальный распознаватель фонем (2000+ языков), PyTorch, CPU.
- Лицензия: **GPL-3.0** — сильный копилефт; при коммерческом использовании проекта
  (Q-04) это риск.
- Вердикт: **не рекомендуется** по R3; держать как план B, если `phonetic` в Rhubarb
  не даст приемлемого качества на русском.

### 4.7. «MLX-совместимый движок» из Q-01

Поддерживаемого MLX-порта lip-sync (Wav2Lip/MuseTalk/LatentSync) на 2026-11-05 не
найдено. Предлагается переформулировать Q-01: не «MLX-модель», а «локальный движок,
работающий на Apple Silicon». Обучение собственной MLX-модели требует датасета котов
и GPU-времени — вне ограничений.

## 6. Рекомендация

**Двухуровневая стратегия.**

1. **Сейчас — виземный 2D-движок на Rhubarb (`pillow_mouth_v3`).** Это реальный переход
   от «громкость → раскрытие» к «фонема → форма рта»: 6–9 форм, тайминги из аудио,
   паузы закрывают рот. Полностью офлайн, CPU, MIT, без миграций, переиспользует
   калибровку и FFmpeg-сборку.
2. **Нейросетевой pixel-level — не начинать.** Условия входа: (а) подтверждённая
   коммерческая лицензия весов, (б) NVIDIA-машина либо подтверждённый MPS-порт,
   (в) датасет кошачьих морд для fine-tune, (г) отдельное решение по памяти/теплу.
   До выполнения всех четырёх пунктов MuseTalk/LatentSync остаются «отложены».

Что НЕ даст уровень 1: фотореалистичный рот, зубы/язык, движение головы и щёк.
Это честно фиксируется в `parameters.limitation` и в названии режима.

## 8. Риски и [ПРОВЕРИТЬ]

| Риск | Влияние | Как проверять |
|---|---|---|
| `--recognizer phonetic` на русской записи даёт грубые фонемы | формы рта реже/неестественно | прогнать на `Lana 6-4.mp3`, сравнить тайминги с огибающей; при необходимости `--dialogFile` с текстом |
| macOS-бинарник требует Rosetta 2 | запуск может не состояться | `rhubarb --version`; при ошибке — установка Rosetta или сборка из исходников |
| Выходные формы < 1 кадра при 24 fps | «дрожание» рта | сглаживание 2–3 кадра в v3; визуальная проверка |
| Детекторы лиц не находят кота (для нейровариантов) | нейровариант нереализуем | шаг 0 плана; результат — в отчёт |
| Q-04 (коммерческий ли проект) не закрыт | влияет на запасные варианты (Allosaurus GPL) | решение человека; Rhubarb MIT безопасен в обоих случаях |
| 82,8 МиБ бинарника вне Git | воспроизводимость установки | фиксировать версию + sha256 в отчёте и `docs/ENV-AUDIT.md` |
