## 4. Аудит по предлагаемым компонентам

Формат: источник идеи → файлы Maestro → лицензионный статус → разрешённый способ
интеграции → сторонние зависимости → ограничения коммерческого использования.

### 4.1. Director: planner/renderer registry и контракт плана

- **Источник идеи:** разделение планировщиков по типу продукта и рендереров по режиму
  (t2v/i2v/a2v/retake/extend), единая схема `ShotPlan`/`ProductionPlan`.
- **Файлы Maestro:** `app/services/director/schema.py`, `director/orchestrator.py`
  (`_PLANNER_MAP`, `_RENDERER_MAP`), `director_pipeline.py`.
- **Лицензионный статус:** WanGP Non-Commercial 1.1 (плюс Community 2.0 для
  унаследованных частей).
- **Разрешённый способ интеграции:** **только** независимая реализация контракта в
  терминах Mary Studio (`visual_scene_plans`, `prompt_revisions`). Копирование dataclass'ов,
  имён полей и структуры один-в-один не требуется и не рекомендуется.
- **Сторонние зависимости:** нет (чистая логика).
- **Коммерческое использование:** копирование запрещено; собственная реализация — без
  ограничений.

### 4.2. Music timeline / beat detection

- **Источник идеи:** BPM, downbeat, энергетические секции, onset envelope, границы
  клипов с ограничениями длительности.
- **Файлы Maestro:** `app/services/audio_analysis.py:110` `_detect_beats`, `:129`
  `_detect_downbeats`, `:140` `_compute_onset_envelope`, `:148` `_segment_sections`,
  `:813` `suggest_clip_boundaries`, `:928` `plan_clip_structure`.
- **Лицензионный статус:** код Maestro — NC 1.1; используемые библиотеки — отдельно:
  `librosa` (ISC), `numpy` (BSD), `faster-whisper` (MIT), `pyannote.audio` (MIT + условия
  моделей), `audio-separator` (MIT).
- **Разрешённый способ интеграции:** самостоятельная реализация через FFmpeg + librosa
  с проверкой лицензий библиотек; никакие функции Maestro не переносятся.
- **Сторонние зависимости:** `librosa`, `numpy`; Whisper/pyannote **не нужны** для MVP
  (транскрипция — отдельное решение).
- **Коммерческое использование:** библиотеки разрешают; модель весов Whisper/pyannote —
  проверить отдельно, если понадобятся.

### 4.3. LLM-планирование со схемой и bounded repair

- **Источник идеи:** grammar-constrained JSON от локальной LLM, батчи, repair-запросы,
  отдельный review-раунд.
- **Файлы Maestro:** `app/services/llm_service.py`, `director/contract_repair.py`,
  `director/validators/*`, `director/planners/music_video.py`.
- **Лицензионный статус:** NC 1.1; Ollama и модель (`gemma3:4b`) — собственные лицензии
  (Gemma Terms of Use).
- **Разрешённый способ интеграции:** использовать существующую интеграцию Ollama Mary
  Studio (`backend/app/planner.py`) + Pydantic-схемы; repair — собственный, с жёстким
  лимитом попыток.
- **Сторонние зависимости:** уже установленная Ollama; новых нет.
- **Коммерческое использование:** проверить условия Gemma при коммерческом использовании
  выходных данных **[ПРОВЕРИТЬ]**.

### 4.4. Production continuity: narrative ledger и physical continuity

- **Источник идеи:** реестр видимых действий и предикатов непрерывности, запрет повторного
  распределения действий между шотами.
- **Файлы Maestro:** `director/music_narrative.py`, `director/physical_continuity.py`,
  `director/policies.py`.
- **Лицензионный статус:** NC 1.1.
- **Разрешённый способ интеграции:** собственная проверка на данных Mary Studio
  (`shot_references`, `prompt_revisions`, инструменты/костюмы в плане).
- **Сторонние зависимости:** нет.
- **Коммерческое использование:** копирование запрещено; идеи свободны.

### 4.5. Job lifecycle / recovery / progress

- **Источник идеи:** атомарные переходы статусов, отмена, чекпойнты, `held` после
  рестарта, ETA по истории.
- **Файлы Maestro:** `app/services/job_lifecycle.py`, `studio_enhancement.py`
  (`StudioJobArchive`), `generation_eta.py`.
- **Лицензионный статус:** NC 1.1.
- **Разрешённый способ интеграции:** **не переносить**. Очередь Mary Studio сильнее
  (PostgreSQL, lease, heartbeat, идемпотентность); брать только отдельные идеи
  (сохранение `prompt_id`, сверка `/history`).
- **Сторонние зависимости:** нет.
- **Коммерческое использование:** не требуется.

### 4.6. Live preview (Tiny VAE) и Generation preview

- **Источник идеи:** кэш превью с ограничением памяти, две ревизии, LRU.
- **Файлы Maestro:** `app/services/generation_preview.py`,
  `docs/Generation-preview.md`.
- **Лицензионный статус:** NC 1.1; Tiny VAE (taesd/taehv) — MIT, декодеры скачиваются.
- **Разрешённый способ интеграции:** **не реализовывать** на текущем стеке: LTX-2.3 MLX
  workflow не публикует промежуточные латенты. Если появится поддержка — реализовать
  собственный bounded-кэш.
- **Сторонние зависимости:** Tiny VAE-декодер (не скачивать без разрешения).
- **Коммерческое использование:** не применимо.

### 4.7. Auto-Tune / hardware presets

- **Источник идеи:** детект железа → профиль настроек; локальная история измерений;
  ручные настройки имеют приоритет.
- **Файлы Maestro:** `app/services/hardware_detect.py`, `perf_recommend.py`,
  `performance_tuning.py`, `docs/Performance-auto-tune.md`,
  `docs/Duration-recommendations.md`.
- **Лицензионный статус:** NC 1.1.
- **Разрешённый способ интеграции:** независимый лёгкий модуль для Apple Silicon

- **Коммерческое использование:** идея свободна; код не переносится.

### 4.8. Editor → FFmpeg filter graph

- **Источник идеи:** один filter graph на весь монтаж (trim, fps, scale, overlay,
  `enable='between(t,…)'`, `atempo`, `drawtext`) вместо многопроходного рендера.
- **Файлы Maestro:** `app/services/editor_projects.py` (`compile_editor_render` :1209,

- **Лицензионный статус:** NC 1.1; FFmpeg — LGPL/GPL в зависимости от сборки.
- **Разрешённый способ интеграции:** собственная, существенно более простая реализация
  (concat + аудио + триммы) на локальном `ffmpeg` 7.1.1. Проверить конфигурацию сборки
  FFmpeg (LGPL или GPL) **[ПРОВЕРИТЬ]**.
- **Сторонние зависимости:** уже установленный ffmpeg.
- **Коммерческое использование:** зависит от сборки FFmpeg; для локального использования
  без распространения ограничений нет.

## 5. Правила clean-room для Mary Studio

Обязательны для любого WP-M*, если он вдохновлён Maestro:

1. **Сначала спецификация.** В документе WP описать требуемое поведение, входы/выходы,
   ошибки и критерии приёмки **без** ссылки на код Maestro как на источник реализации.
2. **Никакого копирования.** Не переносить файлы, классы, имена полей, комментарии,
   строковые константы, тестовые данные.
3. **Никаких ассетов.** Изображения, промпты-примеры, JSON-конфиги, веса, LoRA, чекпойнты
   Maestro не попадают в Mary Studio.
4. **Свои имена и структура.** Контракты Mary Studio выводятся из её домена
   (`Shot`, `RenderAttempt`, `Artifact`), а не из `ShotPlan`/`ProductionPlan`.
5. **Свои тесты.** Тесты пишутся по спецификации поведения; тесты Maestro не
   воспроизводятся.
6. **Проверка на ревью.** В отчёте WP указывать: «код Maestro не использовался, идея
   реализована независимо; проверены лицензии новых зависимостей».
7. **Зависимости.** Каждая новая библиотека — с лицензией и версией в отчёте; пинить в
   `pyproject.toml`/`uv.lock`.
8. **Секреты и внешние API.** Не добавлять ключи и внешние сервисы; MVP остаётся локальным
   (D7/D8 из `docs/DECISIONS.md`).

## 7. [ПРОВЕРИТЬ] и открытые юридические вопросы

| Вопрос | Почему | Как проверить |
|---|---|---|
| Коммерческий статус Mary Studio | от него зависит допустимость использования outputs и любых заимствований | решение человека; при коммерческом использовании — юридическая консультация |
| Условия Gemma (Ollama `gemma3:4b`) для коммерческого использования | модель уже используется в `planner.py` | Gemma Terms of Use, актуальная редакция |
| Лицензия локальной сборки FFmpeg 7.1.1 | LGPL или GPL-конфигурация влияет на распространение | `ffmpeg -version` (флаг `--enable-gpl`), конфигурация сборки |
| Лицензии моделей для будущего TTS/lip sync | модели ещё не выбраны | фиксировать при выборе; без этого WP-M8 не начинать |
| Точная применимость двух лицензий Maestro (NC 1.1 и Community 2.0) к разным частям | в дереве две лицензии | для Mary Studio не имеет значения, пока код не копируется; при любом сомнении — считать строже (NC 1.1) |
| Статус `huggingface_login.js`, `pinokio.js`, `tailscale_setup.js` в корне Maestro | это лаунчер-обвязка Pinokio, не часть лицензии | не использовать и не переносить |
