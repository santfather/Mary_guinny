# 4. Phase B — Director / AI Production Planning

Цель: улучшить существующий планировщик Mary Studio до уровня, позволяющего создавать и выполнять полный производственный план музыкального клипа.

Не создавать новый Director, если аналогичная функциональность уже реализована.

## Возможности

### B1. Music-to-Shot Planning

Вход:
- аудиофайл песни;
- текст песни, если доступен;
- описание сюжета;
- список персонажей;
- визуальный стиль;
- целевое соотношение сторон;
- настройки генерации.

Выход:
- план сцен;
- список Shots;
- временные интервалы;
- персонажи каждого Shot;
- описание окружения;
- стартовые кадры;
- motion prompts;
- предполагаемая длительность;
- порядок генерации;
- монтажный план.

Не использовать один и тот же текстовый prompt для всех кадров без анализа назначения сцены.

### B2. Music Timeline

Использовать FFmpeg и подходящие лёгкие библиотеки для извлечения:
- длительности аудио;
- временной шкалы;
- громкостной огибающей;
- возможных музыкальных переходов.

Опционально исследовать beat detection и segmentation.

Не выдавать эвристически найденные границы за точную структуру песни.

Сохранять возможность ручной корректировки.

### B3. Planning with Ollama

Использовать существующую интеграцию Ollama.

LLM должна формировать структурированный план, а не непосредственно управлять ComfyUI.

Проверять результат через Pydantic schema validation.

Добавить bounded repair для некорректных ответов LLM.

Не допускать бесконечных циклов исправления.

### B4. Production Continuity

Проверять:
- постоянство внешности персонажей;
- правильность инструментов;
- сохранение костюмов;
- логичность переходов;
- наличие необходимых реквизитов;
- соответствие стартового кадра Shot;
- отсутствие нежелательных дополнительных персонажей.

Любое автоматическое исправление должно сохранять ранее утверждённые Shots.

# 13. Обязательные архитектурные ограничения

## Reuse First

Перед созданием нового сервиса искать существующий.

## KISS

Предпочитать минимальные понятные изменения.

## DRY

Не дублировать бизнес-логику.

## YAGNI

Не реализовывать функции, которые не нужны текущему производственному процессу.

## Apple Silicon First

Основной рабочий backend должен оставаться совместимым с Mac M3 Pro.

## Preserve Provenance

Каждый новый результат должен иметь:
- source artifact;
- model/backend;
- параметры;
- seed, если применимо;
- версию workflow;
- Job / RenderAttempt;
- timestamp;
- review status.

## Backward Compatibility

Не ломать:
- существующий CLI `main.py`;
- ComfyUI LTX-2.3 MLX workflow;
- keyframe promotion;
- storage;
- текущие проекты;
- существующие миграции;
- API, используемые frontend.
